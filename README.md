# 京阪ラウンダー

iPhone向けの移動支援PWAの**準備版**です。リアルタイム・時刻表データは未接続です。実際の乗車候補は表示しません。リアルタイム版・時刻表版の完成、実列車の乗車可否の保証はしていません。

## 起動と検証

Node.js 22以上（検証：24.14.1）。外部npmパッケージは不要です。

```sh
npm run build
npm test
npm run dev
```

http://127.0.0.1:4173/ を開きます。変更後はbuildとブラウザ再読み込みを行います。

## 実装済み

- 京阪本線・鴨東線・中之島線46駅、現在駅／目的駅の検索・路線フィルター・お気に入り駅
- 区間反転、お気に入り区間追加／削除／上下移動／1タップ切り替え／前回設定復元
- iPhone幅のUI、大きい操作領域、ライト／ダーク／端末設定、乗車余裕時間
- マニフェスト、192/512pxアイコン、Apple touch icon、静的画面のみのService Workerキャッシュ
- 取得中／正常／遅延更新／通信エラー／未取得／時刻表の状態モデル
- 許諾済みデータ用adapter境界と、列車ごとの実停車列に基づく直接・1回乗換判定（合成テストのみ）
- 到着順比較、乗降可否、指定席未確認・ライナー除外、運休・行先変更、期限切れ除外
- 旧TrainHUDの仕様を基にしたサーバー用取得・正規化の準備モジュール（既定で無効、合成テストのみ）。欠損・古い時刻表・曖昧なIDを安全に扱い、参考情報を乗車候補へ変換しません。

## 未完成・未検証

- 許諾済み運行データ・時刻表の取得。実候補、実遅延、番線、公式予測は表示不可
- 実データ照合、運行中の正確性、臨時運転網羅、2回以上の乗り換え
- 駅別実移動時間を使った接続保証（4分は試験用の保守的な下限で保証ではない）

- 予測誤差を考慮した確率的な先着順位

## データと構造

`src/engine.mjs` はUIから独立。種別名から停車駅を推定しません。取得元が返す列車ごとの順序付き停車列、乗降可否、営業日、現在行先を使います。ライナーは除外します。遅延分だけからETAを生成しません。

`src/adapter.mjs` のendpointは意図的にnullです。設定にtrueを書くだけでデータの法的許諾が成立するわけではありません。契約・保持・再配信・利用目的を確認した後、同一originのサーバー経由で接続してください。APIキーはフロントに入れません。仕様は[docs/DATA_CONTRACT.md](docs/DATA_CONTRACT.md)、調査根拠は[docs/RESEARCH.md](docs/RESEARCH.md)。

合成データはtests内のみです。buildはpublicとsrcだけをdistへコピーし、testsを配信しません。運行データのキャッシュはなく、localStorageには設定だけを保存します。GPS・広告・解析送信はありません。

## 公開

GitHub Pagesの無料枠を使う静的アプリです。mainへの直接pushはせず、featureブランチ→Draft PR→検証→通常マージで反映します。PagesのSourceはGitHub Actionsを設定します。`.github/workflows/pages.yml` がbuild/test後にdistを公開します。PRでは検証のみでデプロイしません。

相対パスのmanifest/start_url/scopeとSWにより、プロジェクトURLのサブパスに対応します。認証情報は不要です。別ホストもHTTPSでdistを配信すれば使用できます。

Service Workerの静的資産を変更したリリースでは`public/sw.js`のCACHEバージョンを更新します。運行APIをキャッシュallowlistに加えないでください。新SWは使用中の旧画面を強制置換せず、次回のアプリ起動で切り替わります。

## 再開

取得部分の移植方針・接続前の具体条件は[docs/KEIHAN_ADAPTER.md](docs/KEIHAN_ADAPTER.md)。`server/`は静的配信に含まれず、HTTPサーバーや定期取得を起動しません。過去に実取得できた技術的記録と、今回の自動取得・業務利用・公開再配信の許諾は区別しています。

[docs/PROGRESS.md](docs/PROGRESS.md)で直近の成果、検証、阻害要因を確認してください。実データが未許諾の間は無断API・PDF取り込みを追加しないでください。既存の別アプリ／別repoは変更対象外です。
