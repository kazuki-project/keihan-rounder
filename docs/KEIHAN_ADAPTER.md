# Keihan adapter preparation — disabled

This is a **server-only reference adapter**, not a live integration or a licensed data service. The PWA endpoint remains `null`; no HTTP server, scheduler, upstream URL, credentials, deployment account, or automatic polling was created. `server/` is not included in the static Pages build. Tests inject synthetic responses from `synthetic.invalid`; they never contact that host.

## Prior technical evidence and scope

The user's existing TrainHUD project was inspected read-only. Its saved report records 41 trains with status `ok` and source time 2026-09-28 12:46:50 JST, and another report records 25 trains at 2026-09-29 00:02:28 JST. The earlier provider joined position and departure-reference JSON using `wdfBlockNo`; its shared backend limited fetching to once per minute. Those saved reports establish historical reported retrieval, not current availability, accuracy or redistribution rights. No old payload, settings, secrets, database, logs or old app files were copied into this repository. No upstream request was made during this work.

The parser is adapted from that user's earlier provider's field contract. The grid interpretation remains explicitly `legacy-grid-unverified`. A third-party parser's software license does not grant rights to the transport operator's data. No third-party source or captured railway dataset was imported here.

## Modules and safe behavior

- `server/keihan-reference.mjs`: pure normalization. Missing or malformed delay is `null`, not zero. Unknown direction stays `unknown`. Type is only a supplied label, never guessed from number/stopping pattern. Position does not establish boarding state. Source timestamps are explicit JST and strictly checked. No arrival/prediction is inferred from a departure, grid location or delay.
- A join requires an independently established service date for **both** datasets, evidence of that mapping, fresh source timestamps and unique canonical block IDs. IDs include the service date. Duplicate IDs fail closed. Missing/old/mismatched timetable produces position reference only; the failed join never becomes a boarding candidate. A valid departure reference is still not a complete timetable trip. `99:99` means a pass marker only; missing departures are not silently treated as stops.
- `server/keihan-provider.mjs`: disabled by default, explicit reviewed server configuration required. Bounds JSON payloads, accepts only JSON over a configured HTTPS origin, refuses redirects, coalesces requests, applies a reviewed interval of at least 60 seconds and sanitizes transport errors. It installs no timer or retry. Every refresh re-evaluates source freshness. Failed timetable retrieval never falls back to a previously successful table. Observation regression is rejected within the provider instance, including after transport failure.
- Every result is `kind: keihan-reference` with `candidateFeed: null`. The existing boarding engine rejects it. Unknown cancellation, reservation rights, complete stops, arrivals and live boarding status cannot be invented. There is intentionally no conversion to the PWA's complete feed contract.

The 60-second minimum is a conservative software floor, not evidence of allowed usage.
5. To enable **boarding candidates**, acquire a complete authorized feed: actual ordered stops, pickup/dropoff, scheduled arrivals and departures, current cancellation/change status, ticket policy, boarding status, service calendar and reliable source revisions. Add durable server-side snapshot ordering across process restarts, same-revision contradiction detection, an expiration/withdrawal mechanism for permission, endpoint access policy, production observability and source reconciliation. The prepared provider's observation watermark is memory-only; the browser guard is also instance-only. Neither proves durable ordering or revision identity. Only after these checks, enable the backend and change the PWA endpoint in a reviewed PR.
